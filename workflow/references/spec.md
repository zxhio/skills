# Spec 编写规则

以能准确表达当前结论的最小结构编写。简单方案允许只有列表；内容增多时再分节。仅记录当前粒度已确定的内容，不为完整性补充细节。未确定的问题按需标注。

## 内容规则

1. 按用户指定的主题和文档类型限定范围；每份文件描述该范围内的变更。
2. 开头列修改汇总，每项写清对象、操作和修改内容。简单方案使用列表，多个对象需要对照时使用表格。
3. 汇总已能表达结论时结束。需要展开时，以变更对象为章节标题，每个详情块对应一项汇总。
4. 详情只写具体定义及其说明。SQL、字段定义或示例已表达的内容写一遍，正文补充其中未表达的含义。
5. 正文直接描述当前结论。已讨论但尚未确定的问题标记为“待定：……”，数值、策略和默认值采用已确认的结论。
6. 保存前逐段核对：每段应属于修改汇总、具体定义、定义说明或已讨论的待定项；其余内容删除。

## 按类型展开

| 类型 | 详情范围 |
| --- | --- |
| SQL | 表、字段、索引、约束、变更 SQL、本次涉及的数据转换 |
| API | 接口、请求和响应变化、错误行为、兼容规则 |
| 部署 | 制品、配置、执行步骤、检查方式、恢复操作 |
| 其他 | 用户明确指定的变更对象和内容 |

详情深度采用当前讨论已确定的粒度。只有字段变化结论时记录字段变化；已确定 SQL 时保存 SQL。
